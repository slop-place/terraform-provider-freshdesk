# Freshdesk Provider

~> **This provider is 100% AI-generated.** Every line of it — the client, the
resources, the tests and this documentation — was written by Claude, not by a
human. It has been exercised against a live Freshdesk account, and the
acceptance suite covers every resource and data source, but no human has
reviewed the code line by line. Read it before you trust it with a production
helpdesk.

Manage a [Freshdesk](https://freshdesk.com) helpdesk as code. The provider covers
the whole of the [Freshdesk API v2](https://developers.freshdesk.com/api/):
agents and groups, contacts and companies, ticket and contact fields, SLA
policies, automation rules, the knowledge base, community forums, mailboxes and
tickets themselves.

## Getting an API key

Sign in to the agent portal, open **Profile picture → Profile Settings**, and
copy the API key shown on the right. The key inherits the permissions of the
agent it belongs to, so use an administrator's key to manage configuration.

## Example usage

```terraform
terraform {
  required_providers {
    freshdesk = {
      source  = "slop-place/freshdesk"
      version = "~> 0.1"
    }
  }
}

# Credentials are read from FRESHDESK_DOMAIN and FRESHDESK_API_KEY when they
# are not given here.
provider "freshdesk" {
  domain  = "acme" # or "acme.freshdesk.com"
  api_key = var.freshdesk_api_key
}

variable "freshdesk_api_key" {
  type      = string
  sensitive = true
}
```

## Authentication

Credentials may be given in the provider block or through the environment:

| Argument  | Environment variable                       |
|-----------|--------------------------------------------|
| `domain`  | `FRESHDESK_DOMAIN` (or `FRESHDESK_URL`)    |
| `api_key` | `FRESHDESK_API_KEY`                        |

The provider block wins where both are set.

## Rate limiting

Freshdesk enforces a per-hour request budget that varies by plan. The provider
retries a throttled response (HTTP 429) automatically, honouring the
`Retry-After` header, and backs off exponentially on transient 5xx errors. Raise
or lower `max_retries` to suit; set it to `-1` to disable retries entirely.

## What the API cannot do

A few Freshdesk endpoints accept no delete, whatever the documentation says.
Destroying one of these resources removes it from Terraform state and emits a
warning; the record itself stays until it is removed in the portal:

- `freshdesk_sla_policy` — deactivate it with `active = false` instead
- `freshdesk_canned_response`
- `freshdesk_canned_response_folder`

Several attributes are normalised by Freshdesk and so cannot be compared
byte-for-byte. Email addresses are folded to lower case and compared
case-insensitively. HTML bodies (`freshdesk_ticket.description`,
`freshdesk_canned_response.content_html`) are rewritten by the server, so the
provider keeps what you configured and exposes the stored rendering separately;
an edit made in the portal will not show as drift.

## Schema

### Optional

- `api_key` (String, Sensitive) Freshdesk API key, found under Profile Settings in the agent portal. May also be set with the `FRESHDESK_API_KEY` environment variable.
- `domain` (String) Freshdesk domain. Accepts a bare subdomain (`acme`) or a full host (`acme.freshdesk.com`). May also be set with the `FRESHDESK_DOMAIN` environment variable (`FRESHDESK_URL` is accepted as an alias).
- `max_retries` (Number) How many times to retry a throttled (HTTP 429) or transient (HTTP 5xx) response. Defaults to `5`. Set to `-1` to disable retries.
- `timeout_seconds` (Number) Per-request timeout in seconds. Defaults to `60`.
- `user_agent` (String) Value sent in the `User-Agent` header. Defaults to `terraform-provider-freshdesk`.
